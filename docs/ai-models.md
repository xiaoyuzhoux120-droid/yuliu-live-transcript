# AI 模型接入与成本（线程 C）

本文说明翻译、润色与会议总结所用文本模型的接入方式、两种运行模式、成本基准和后续计划。语音转文字（ASR）不在本文范围内。

## 1. 原实现的问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | DeepSeek `deepseek-flash` / `deepseek-v4-pro` 默认开启思考模式，旧代码没有关闭 | 每句短翻译都额外生成推理 token：费用更高，字幕译文多等几秒 |
| 2 | 每句识别结果单独发一个翻译请求，不带上文 | 请求多，容易触发 429；代词和术语前后译法不一致 |
| 3 | 翻译只在 `config.key` 非空时触发 | **Bug**：Ollama（无需 Key）只能总结，不能实时翻译 |
| 4 | 总结一次性发送整场转写 | 长会议会超出本地 8B 模型（Ollama 默认上下文约 2–4K）或 Groq 免费档 TPM 限制，内容被静默截断 |
| 5 | 总结要求模型输出自由文本 | 行动项、负责人、期限无法结构化展示和复制；模型容易把“提议”当成“决定” |
| 6 | 没有超时、重试，也不处理 `<think>` 标签 | 请求可能一直挂起；qwen3 / R1 类模型会把思考过程显示到字幕里 |
| 7 | 每次失败都弹提示 | Key 错误时每句都弹一次 |
| 8 | 不统计用量 | 用户不知道一次会议花了多少钱 |

## 2. 新架构

新增 `public/ai-engine.js`（纯逻辑，不访问 DOM，挂载为 `window.YuliuAI`），`public/transcript.js` 只保留 UI 接线。

```
识别结果 addLine ──► Translator.enqueue
                      ├─ needsTranslation：语气词 / 已是目标语言 → 跳过
                      ├─ LruCache：重复句直接返回
                      └─ 省钱：6 秒窗口内合并为一次 JSON 批量请求
                         高质量：逐句立即发送 + 4 句上文
                              │
                              ▼
                      chatCompletion（超时 30s、429/5xx 指数退避并读取 Retry-After、
                                      空白内容重试、清洗 <think>、记录 usage）
结束录音 ──► Translator.flush ──► Summarizer.summarize
                                   ├─ 合并同一说话人的连续句子以减少 token
                                   ├─ 未超预算：单次请求
                                   └─ 超预算：分段提取（结果缓存）→ 合并；合并失败时在本地兜底合并
                                   输出 JSON：title / summary / key_points / decisions /
                                             action_items{task, owner, due} / open_questions
```

### 模型路由

| 服务 | 省钱：翻译 / 总结 | 高质量：翻译 / 总结 |
|---|---|---|
| DeepSeek | deepseek-flash（非思考）/ deepseek-flash（非思考） | deepseek-flash（非思考，带上文）/ deepseek-v4-pro（思考） |
| 硅基流动 | Qwen3-32B（`enable_thinking:false`） | 用户模型 / DeepSeek-R1 |
| Groq | gpt-oss-20b（`reasoning_effort:low`） | gpt-oss-20b / llama-3.3-70b-versatile |
| OpenRouter / Ollama / 自定义 | 沿用用户填写的模型 | 沿用用户填写的模型 |

- 用户改过“模型名称”时，以用户填写的为准。“总结模型”一栏可以单独指定总结用的模型。
- 推理参数只发给明确支持它的服务，避免严格校验参数的接口返回 400。
- 本地和自定义模型不设 `max_tokens`，避免思考型模型在思考阶段就被截断。

### 缓存

1. **服务端前缀缓存**：在同一次会话里，翻译和总结的 system 提示（含术语表）保持不变，并放在消息最前面。DeepSeek 默认开启磁盘前缀缓存，命中部分按约 1/50 的价格计费（`usage.prompt_cache_hit_tokens`）。
2. **本地 LRU 缓存**：缓存键是模型、目标语言、术语表哈希加原文。重复句不会再发请求。
3. **总结分段缓存**：长会议“继续录音”后再次总结时，旧的分段直接复用缓存，只重算新增的分段和最后的合并。

### 准确性措施（总结）

- 提示中明确：“决定”只收录明确达成一致的事项；行动项必须有人承诺；负责人和期限只能来自原文，否则写“未指定”。
- 使用 JSON 输出模式（DeepSeek、Groq、Ollama、OpenRouter 支持 `response_format: json_object`）并宽松解析。解析失败时保留原文作为摘要。
- 时间线格式为 `[mm:ss] S1: …`，让模型在结论里保留说话人归属。
- 术语表同时用于翻译提示，保证专有名词译法一致。

## 3. 成本基准（离线 mock）

运行 `npm run bench:ai`。场景：60 分钟中文会议，720 句（约每 5 秒一句，其中 40% 是“嗯 / 好的 / 对 / OK”这类语气词），翻译成英文。价格按 DeepSeek 2026-08 起的**高峰价**估算，是上限。

| 方案 | 请求数 | 跳过 / 缓存 | 输入 token | 前缀缓存命中 | 输出 token | 估算费用 |
|---|---|---|---|---|---|---|
| 旧实现（假设每句思考 150 token） | 721 | 0 | 42,186 | 10,800 | 119,669 | $0.153 |
| 旧实现（假设没有思考 token） | 721 | 0 | 42,186 | 10,800 | 11,669 | $0.024 |
| **省钱模式** | **361** | 288 | 76,050 | 48,753 | 9,953 | **$0.020** |
| 高质量模式 | 433 | 288 | 95,270 | 57,754 | 11,021 | $0.041 |

结论：

- 最大的节省来自关闭翻译的思考模式。按假设值估算，省钱模式费用约下降 87%，同时每句译文少等推理时间。思考 token 的真实数量需要用真实 Key 验证。
- 即使旧实现没有思考开销，省钱模式也能少一半请求，费用约低 13%。少一半请求同时降低了 429 风险。
- 高质量模式的费用约为省钱模式的 2 倍，主要用于带上文的逐句翻译和 v4-pro 总结，换来更好的术语一致性和总结质量。
- 按 DeepSeek 的价格，一小时会议的文本模型费用都在几美分以内，所以**延迟和准确性比费用更关键**。费用对 OpenRouter 上的高价模型更敏感，那里会直接读取 `usage.cost`。
