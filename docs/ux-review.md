# 语流 · UI/UX 与产品体验审查（线程 D）

> 范围：`/app` 转写工作台（`app/app/transcript.html` + `public/transcript.js`）。不涉及 ASR、模型路由与安全实现细节（见线程 B / C / E）。
> 审查日期：2026-11-24。所有验证均在本地无麦克风、无 API Key、无付费调用的条件下完成。

## 1. 现状结论

界面视觉干净、品牌一致，首屏信息层级清楚。但它目前更像“一次性演示页”，还不是能撑住一场 2 小时会议或一学期课堂的工作台。主要问题集中在 **数据会丢、长内容会卡、读不回去、带不走**。

### 1.1 已确认的问题（按影响排序）

| # | 问题 | 影响 | 证据 |
|---|------|------|------|
| 1 | 没有任何持久化，“最近记录”按钮只弹提示 | 刷新、误关标签页、浏览器崩溃 = 整场会议丢失 | `historyBtn` 仅 `toast(...)` |
| 2 | 点“体验演示”会**直接清空**当前真实转写 | 一次误点丢掉全部内容 | `runDemo()` 首行 `lines = []` |
| 3 | 每次中间结果都重建整个字幕列表（`innerHTML`） | 长会议越录越卡，2,000 段时每次更新约 **186 ms**；也会打断用户选中复制 | 基准测试见 §4 |
| 4 | 每次更新都强制滚到底部 | 会中想回看前文会被不停“拽”回底部 | `render()` 末尾无条件 `scrollTop = scrollHeight` |
| 5 | “继续录音”后时间戳从 00:00 重新开始 | 时间轴错乱，无法对齐录像/回放 | `startSession()` 重置 `startTime` |
| 6 | 只能复制，不能导出；移动端（≤520px）连复制按钮都被隐藏 | 会后无法交付纪要/字幕 | `.actions .iconbtn{display:none}` |
| 7 | 识别错的字无法修改；说话人只能叫“说话人 N” | 纪要质量依赖 ASR 一次正确 | — |
| 8 | 新增说话人按钮闭包 Bug：添加说话人 4 之后点“说话人 3”会选中 4 | 说话人标注错乱 | `button.onclick = () => selectSpeaker(speakerCount)` |
| 9 | 右下“会话洞察”是固定的营销文案，占据工作区 | 浪费屏幕，没有实际信息 | — |
| 10 | 复制内容、摘要标签硬编码中文，英文界面下不一致 | 双语体验割裂 | — |

## 2. 同类产品调研与差异化

| 产品 | 强项 | 对语流的启发 |
|------|------|--------------|
| Otter.ai / Fireflies / Fathom | 会议机器人自动入会、搜索、AI 问答、集成 CRM | 搜索 + 重点标记 + 导出是“基本盘” |
| Granola | 不入会、本地采音，把 AI 总结叠加在用户自己的笔记上 | “人写要点 + AI 补全”比纯自动纪要更可信 |
| Notta / Tactiq | 多语言、实时翻译、Chrome 插件抓字幕 | 双语视图切换、SRT 导出 |
| 通义听悟 / 飞书妙记 / 讯飞听见 | 中文识别强、章节速览、发言人统计、关键词 | 发言占比统计、课堂/访谈场景模板 |
| Teams / Zoom 实时字幕 | 大字幕投屏 | 课堂投屏需要“字幕模式” |

参考：[TechRepublic 2026 会议记录工具评测](https://www.techrepublic.com/article/news-best-ai-meeting-note-takers-2026/)、[Granola: Best meeting transcription software in 2026](https://www.granola.ai/blog/best-meeting-transcription-software-in-2026)、[Sonix: Otter vs Granola](https://sonix.ai/resources/otter-vs-granola/)、[知乎：主流会议记录 APP 实测对比](https://www.zhihu.com/tardis/jm/art/2048002632485279630)、[B 站：AI 会议纪要工具对比](https://www.bilibili.com/read/cv50475661)。

**语流的差异化定位：“不入会、不上传、中英混说”的个人双语记录台。**

1. **隐私优先**：浏览器识别 + 本地历史 + 自带 Key（BYOK），录音默认不离开设备。大厂工具普遍需要上传音频到其云端。
2. **中英混说与双语对照**是一等公民（视图切换、双语字幕投屏、双语 SRT），而不是“附加翻译”。
3. **场景模板**：会议 / 课堂 / 访谈各自的说话人预设与总结结构（课堂出知识点和作业，访谈出问答与可引用原话）。
4. **人机协作纪要**：会中一键“标记重点”，会后摘要和导出优先围绕人工标记的时刻展开（Granola 思路，在中文市场少见）。

## 3. 本分支已实现的改进（`thread-d/ux-transcript-workspace`）

| 改进 | 解决问题 | 说明 |
|------|----------|------|
| 本地历史记录（最近记录抽屉） | #1 | 自动保存到 `localStorage`（不含音频、不含 API Key），可打开、继续录音、导出、删除；可关闭自动保存、一键清空；超配额时自动淘汰最旧记录并提示导出 |
| 演示不再清空真实转写 | #2 | 先把当前记录存入历史；演示内容不写入历史；演示后开始真实录音会自动新建会话 |
| 增量渲染 | #3 | 只更新变化的段落；2,000 段时中间结果更新从 ~186 ms 降到 ~3 ms |
| 智能跟随滚动 + “↓ 回到最新” | #4 | 只有在底部时才自动跟随；回看时显示回到最新按钮 |
| 时间轴连续 | #5 | “继续录音”沿用累计时长；历史记录恢复后也能接着录 |
| 导出菜单 | #6 | Markdown 会议记录（含摘要、重点标记、完整转写）、TXT、SRT 双语字幕、复制全文；移动端可用 |
| 行内校对 | #7 | 双击或点 ✎ 修改识别文字（Enter 保存 / Esc 取消），标记“已校对”；连接模型时自动重译 |
| 说话人改名 + 场景预设 | #7 | 双击说话人按钮改名；课堂（老师/学生）、访谈（主持人/嘉宾）；场景会向摘要提示词追加一句结构要求 |
| 说话人按钮闭包 Bug | #8 | 已修复 |
| 实时会话洞察 | #9 | 时长、字/词数、段落数、重点数、发言占比、重点时刻快速跳转 |
| 搜索 | — | 高亮 + 计数，Enter / Shift+Enter 在结果间跳转 |
| 视图与字号 | — | 双语 / 仅原文 / 仅译文，A− / A+（偏好记忆在本机） |
| 字幕模式（投屏） | — | 全屏大字双语字幕，适合课堂与线下活动；C 打开、Esc 退出 |
| 标记重点 | — | 按钮或 M 键标记最近一句，导出时单列“重点标记” |

## 5. 产品升级路线图（UX 视角）

**v0.2（本分支 + 小步快跑）**
- 合入本分支；与线程 A 的 `transcript.js` 重构对齐（本分支改动集中在 `render()` 与文件末尾的 Workspace UX 区块，冲突面可控）。
- 与线程 E 对齐本地历史的隐私边界：是否加“退出登录时清除本地记录”、是否对历史做可选加密（WebCrypto + 用户口令）。

**v0.3（体验深化）**
- 结构化摘要卡片：把 AI 输出拆为“结论 / 决定 / 行动项（负责人、截止日）”，行动项可勾选、可复制为待办（依赖线程 C 输出 JSON）。
- 章节速览：按时间自动分段并生成小标题，长课堂可按章节跳转。
- 术语表：每个会话/课程可维护专有名词表，同时用于 ASR 提示与翻译（与线程 B 合作）。
- 说话人自动分离结果的“人工确认”交互：批量改名、合并说话人。

**v0.4（差异化）**
- 会中 AI 问答（“刚才谁说了预算？”），只基于本地转写上下文。
- 课堂模式：PPT/讲义导入作为上下文、复习卡片导出（Anki CSV）。
- 访谈模式：引用摘录板，一键生成带时间戳的引述。
- PWA 离线安装、IndexedDB 存储替代 localStorage（容量更大），可选同步。

## 6. 已知限制

- 历史记录存在浏览器 `localStorage`，与同源页面共享，清除浏览器数据会丢失；容量约 5 MB（约数十场长会议），超出时淘汰最旧记录并提示导出。
- 字幕模式依赖浏览器 Fullscreen API；不支持时以页面内全屏遮罩显示。
- 行内编辑后的重译、场景化摘要提示词会产生额外的模型调用（仅在用户已配置文本模型时）。
